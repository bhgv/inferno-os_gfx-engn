# Регрессии экспериментального рендера: владение и границы

[English](README.md) · [Renderer](../render.c) · [PNG](../aux_png.c) ·
[Граница событий](../channel_wrk.c)

Параллельный renderer найден в `render.c`: отдельный `kproc` создавался для
каждого грязного узла, ожидание шло по обычным изменяемым флагам. Текстовый
`aux_text.c` дополнительно использует общие данные FreeType. Исправления сделаны
в этой графической репозитории; GUI-движок не переносится в Dis-ядро FlashVM.

## Исправлено

- Fallback с NULL разыменовывал `el`. Упакованные float читались без выравнивания,
  команды/строки — без проверки конца. Теперь весь поток проверяется заранее,
  float копируются в выровненные локальные значения.
- Терминатор TEXT потребляется. Неизвестные/оборванные/nonfinite команды
  отвергаются. Размеры проверяются до преобразования в int/выделения: до 16M
  пикселей на image и до 32768 на ось.
- Завершение публикуется через защищённую запись задания. До повторного
  использования стека/чтения surface и границ выполняется join. Обычный WAIT-флаг
  больше не используется как несинхронизированная публикация между native-потоками.
- Независимые листья идут порциями по восемь. Текст, зависимые маски и вложенные
  canvas обрабатываются владельцем после завершения предыдущих работ. Это
  устраняет гонку общего текстового helper и сохраняет порядок композиции;
  постоянный пул пока не реализован.
- WAIT снимается на каждом обычном выходе, в том числе для неизвестного типа
  и неудачного image. PNG теперь диспетчеризуется; пустой canvas конечен и прозрачен.
- Общая surface кадра сериализована и пересоздаётся при изменении размеров.
  Выполняются flush и копирование по stride Cairo, с фиксированным ARGB32.
  Нулевые/nonfinite преобразования пропускаются, не портят общий Cairo-контекст.
- PNG добирает короткие `kpread` до точной длины, отвергает EOF/ошибку/overflow
  смещения и не закрывает/не декодирует неоткрытый дескриптор.
- `arevt` — нативные координаты. `D2H(arevt)` обращался к несуществующему Heap.
  Новый массив владеет копией скаляров; ошибочного retain больше нет.

## Запуск проверок

Из корня репозитории, с C-компилятором, pthreads и библиотекой Cairo image:

```sh
mkdir -p build/tmp
TMPDIR="$PWD/build/tmp" python3 libinterp/graph/tests/render_regression.py
# При необходимости задайте CC и GRAPH_CAIRO_LIBS с явным путём к Cairo.
```

Драйвер компилирует **production-тела** рендера/PNG, использует поставленные
объявления Cairo и настоящую нативную библиотеку image. Границы процессов/locks/
файлов адаптированы к pthreads и контролируемому I/O; SVG/текст возвращают реальные
независимые Cairo-surfaces. Проверяются packed/truncated входы, 300 узлов,
ограниченная параллельность, owner-only текст, терминальные флаги, повторный resize,
короткие чтения/EOF/ошибки PNG и независимая копия touch. Полная ОС/окно не собираются.

По умолчанию включены AddressSanitizer/UBSan. LeakSanitizer явно выключен:
песочница разработки не предоставляет `/proc` для метаданных потоков; проверка
утечек этим не заявляется. Старый renderer `7273ec7` на том же тесте воспроизводит
UB разыменования NULL. `GRAPH_RENDER_SOURCE` позволяет указать сохранённый baseline.

## Оставшиеся ограничения

На весь синхронный кадр вызывающий удерживает неизменяемый **ациклический** граф,
payload узлов, display-буфер и конфигурацию экрана. Локальный frame-lock не
синхронизирует произвольные внешние изменения/освобождение/resize. Raster callback
не исполняет AS/Dis и не вызывает allocator VM. Разным VM нужны отдельные владельцы
и кучи, задания передаются копиями.

Join пока кооперативно опрашивается через `osyield` под настоящим lock; pool с
ожиданием — следующий шаг. Завершение OS-thread может отставать от callback,
поэтому восемь — граница порции заданий, не всех временных служебных потоков ОС.
Scratch-canvas пока 2000×2000. Большие вложенные canvas, циклы, полный аудит
текста/ресурсов и безопасная мутация во время рендера ещё не завершены. Touch-тест
исправляет один retain, не весь старый канал/GC-протокол. Нативные окна
Windows/macOS/Android и полная сборка ОС здесь не проверялись.

Незавершённый `E.getLevelsList` теперь явно сообщает об отсутствии реализации.
Он больше не разыменовывает неинициализированный результат и не подменяет данные
VM Array адресом нативного списка. Настоящее типизированное преобразование ещё нужно.
